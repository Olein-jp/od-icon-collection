## 変換処理

Lucideは線画主体であり、既定の変換では円・曲線を含む4件がRGBA差分率0.5%の基準を超えた。判定基準を変更せず、Lucideだけ作業座標を64倍にして線の輪郭を生成し、最後に元の座標へ戻す方式を追加した。輪郭近似の許容値を元座標で0.001単位、出力座標を小数第3位に設定し、描画比較の基準を保ちながらファイルサイズを抑える。作業倍率は2の累乗を採用し、座標の浮動小数点変換による不安定さを抑える。元SVGとviewBoxは保持し、配布SVGは塗りパスとcurrentColorを使用する。

既存ライブラリは同じ変換経路を維持し、生成物のハッシュが変わらないことを照合する。追加依存パッケージは不要で、固定済みのpicosvg/Skiaだけで再現できる。

円の面積が理論上の線輪郭面積と近似することを単体テストで確認し、全件の描画比較も再実施する。元データ・ライセンス・コミットの検証、危険なXML/属性/参照の拒否も継続する。

## 設定と更新時の扱い

新規インストールでは4コレクションを有効とする。既存の保存済み設定には自動でLucideを追加せず、利用者の選択を保持する。更新後は「設定 → OD Icon Collection」でLucideを有効化できる。既存のアイコン名・保存本文・色やサイズの属性を変更しない。

### 応答とデータ量

WordPress 7.1.4 / PHP 7.4.33、独立したCLIプロセスで標準RESTコントローラーを計測。全件はcoreの88件を含む8,784件で約949ms、JSON約15.28MB、PHPピーク90.5MiB。Lucide単独は2,015件、約921ms、JSON約8.44MB。これらは圧縮前のJSON量であり、ネットワーク転送時間は含まない。

初期の高精度出力から輪郭の許容誤差と小数桁を調整し、LucideのJSONを約18.2MBから約8.44MBへ軽量化。画像比較の判定基準は変更していない。線画を輪郭に展開するため、元SVGより大きくなる。WordPress標準APIはコレクション絞り込み前に全件を読み込む制約があるため、必要なコレクションだけ有効にする運用が有効。独自APIへの置き換えは行わない。
